# GWP(증정)가 11월 가격 계획에 반영되지 않은 건

작성 2026-11-27 · 대상 11월(2026-11) DTC 가격 계획 · 품목 Music Studio(LS51H, LS71H) 외

---

## 1. 무엇이 일어났나

11월 2일부터 25일까지 CE 프로모션에 **Gift with Purchase**(`GWP-Music
Studio(LS51H)`)가 운영되었습니다. 해당 기간 증정품은 **금액 0원**으로 출고되었고,
계획 가격은 증정 사실을 반영하지 않은 통상가로 수립되어 있었습니다.

| 품목 | 계획가(GSCM) | 실현가 | 차이 |
|---|---|---|---|
| HW-LS51H/XY | 208 | **14** | −194 |
| HW-LS71H/XY | 312 | **29** | −283 |

실현가가 계획가의 **7~9% 수준**입니다. 일반적인 프로모션 할인(통상 10~50%)과는
자릿수가 다른 괴리이며, 이는 할인이 아니라 **대부분의 수량이 무상 출고**되었기
때문입니다.

## 2. 왜 반영되지 못했나

네 가지가 겹쳤고, 각각 단독으로도 누락을 만들 수 있는 구조였습니다.

### 2-1. 가격 산정 축이 "할인율"이어서 증정이 들어갈 자리가 없음

현행 가격 산정은 **과거 실현 ASP를 기준으로 주요 프로모션의 할인율을 반영**하는
구조입니다. GWP는 가격을 깎는 행위가 아니라 **별도 품목을 무상 제공**하는
행위이므로, 할인율 축에 올릴 값 자체가 없습니다. 프로모션 테이블에서도
`Offer_Detail`에 금액(`$`)도 비율(`%`)도 적히지 않습니다.

결과적으로 자동·수동 어느 경로로도 "이 품목은 이번 달 대부분을 0원에 내보낸다"는
신호가 가격 산정에 전달되지 않았습니다.

### 2-2. 증정품이 프로모션 테이블에서 **자기 행을 갖지 않음**

GWP 라인은 **구매하는 제품**(사운드바 MRA 계열)의 행에 등록되고, 증정품은
`Offer_Detail` **본문 괄호 안의 텍스트**로만 존재합니다.

```
행 소유자: MRA-Q990F      Offer_Type: Gift with Purchase
                          Offer_Detail: GWP-Music Studio(LS51H)
```

따라서 증정품 SKU(LS51H) 기준으로 프로모션 테이블을 조회하면 **그 달에 아무
프로모션도 없는 것으로 보입니다.** 가격을 매기는 단위는 SKU인데, 프로모션이
붙어 있는 단위는 다른 SKU입니다.

### 2-3. 실적 데이터에서 무상 출고분이 제외되고 있었음

판매 원장에서 **수량은 있고 금액이 0인 라인**을 "nil"로 분류해 집계에서
제외하고 있었습니다. 이 때문에 과거 실현 ASP가 **유상 판매분만의 평균**으로
계산되었고, 증정이 있었던 달조차 ASP상으로는 정상가로 보였습니다.

즉 **계획에도 없고(2-2) 실적에도 안 보이는(2-3) 이중 누락**이었습니다.

### 2-4. 신규 운영이라 참조할 과거가 없음

이번 GWP는 해당 품목에 대해 처음 운영된 건으로, 과거 6개월 창에 무상 출고
이력이 없습니다. 과거 기반 모델은 전례가 없는 사건을 추정할 수 없습니다.

## 3. 재발 방지 대책

### 3-1. 데이터 — 무상 출고분을 실적에 포함 **(반영 완료)**

판매 원장 집계에서 금액 0원 라인을 더 이상 제외하지 않습니다. 마이너스 라인
(반품·취소)만 제외합니다. 출고된 수량은 계획에 잡힌 수량이므로, 실현가는
무상분을 포함한 **출고 기준 평균단가**로 산출됩니다.

실행 시 포함 건수를 로그에 표시해 누구나 확인할 수 있게 했습니다.

### 3-2. 시스템 — 증정품을 `Offer_Detail`에서 해석해 증정품 SKU에 귀속 **(반영 완료)**

GWP 라인을 읽어 괄호 안 모델명(`LS51H`)을 실제 판매 코드(`HW-LS51H/XY`)에
연결하고, **구매 제품이 아니라 증정품**의 해당 기간을 "증정일"로 표시합니다.
모델명이 적히지 않은 경우 증정품 명칭을 프로모션 테이블의 제품 설명과 대조해
찾습니다.

**단, 명칭이 여러 제품에 걸리면 어느 것도 표시하지 않습니다.** `Music Studio`는
LS50H·LS51H·LS70H·LS71H가 공유하는 패밀리명이므로, 명칭만으로는 증정품을
특정할 수 없습니다. 추정으로 표시하면 증정하지 않은 품목까지 가격이 왜곡됩니다.

### 3-3. 시스템 — 증정일을 별도 기준으로 가격 산정 **(반영 완료)**

증정일은 일반 프로모션일과 분리해 다음 순서로 가격을 매깁니다.

1. 해당 품목의 **과거 증정일 실적** — 무상 비율을 실제 데이터에서 읽음
2. 동일 그룹의 과거 증정일 실적
3. 전례가 없으면 **0원 기준** — 증정은 정의상 0이며, 통상가보다 0이 훨씬 정확한
   추정입니다

LS51H의 경우 3번이 적용되어 **10.4**로 산출됩니다(실현 14). 기존 로직은 86이었습니다.

### 3-4. 프로세스 — 프로모션 등록 규칙 **(요청 사항)**

시스템 보완으로 대부분 자동 처리되지만, **원천 데이터에 두 가지가 있으면
추정이 아니라 사실로 처리됩니다.**

| 항목 | 요청 내용 |
|---|---|
| **증정품 SKU** | `Offer_Detail` 본문이 아닌 **별도 필드에 full model code**로 기입. 패밀리명(`Music Studio`)만 기입 시 특정 불가 |
| **증정 예상 수량** | 증정 대상 수량(또는 구매 대비 증정 비율)을 함께 등록. 무상 비율을 추정하지 않고 계획에 직접 반영 가능 |

괄호 표기(`GWP-Music Studio(LS51H)`)도 현재는 읽히지만, 표기 방식이 바뀌면
다시 놓칠 수 있는 구조입니다. 별도 필드가 근본 대책입니다.

### 3-5. 운영 — 월초 점검 항목

가격 산정 실행 시 다음 세 줄이 출력됩니다. **월초 가격 확정 전 확인합니다.**

```
N line(s) at nil revenue, kept
N gift-with-purchase line(s) in the plan: N resolved by the model in the
  brackets, N by what the gift is called
N name a family rather than a model - several products answer to it, so
  none is marked
```

세 번째 줄이 0이 아니면 **증정품이 특정되지 않은 GWP가 있다는 뜻**이며, 해당
건은 수기로 증정품 SKU를 확인해야 합니다.

## 4. 남은 한계

- **무상 비율은 전례가 있어야 읽을 수 있습니다.** 전례가 없으면 0원으로
  가정하므로, 증정 기간에도 유상 판매가 상당한 품목은 과소 추정됩니다.
  3-4의 증정 예상 수량이 등록되면 해소됩니다.
- **증정품 명칭이 패밀리명뿐이면 자동 특정이 불가합니다.** 설계상 추정하지
  않으므로 누락으로 남고, 3-5의 점검에서 잡아야 합니다.
